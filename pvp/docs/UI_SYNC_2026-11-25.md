## Guaranteed exact-card thumbnail policy

1. The **250** face-up card IDs have a 96×134 WebP miniature embedded as a data URL inside the source-verified `pvp-card-thumbnails.js`, matching the latest VS AI donor. The **same 250** compressed WebP files are also kept as separate assets. This trades ~1 MB of initial JS data for a self-contained face image on slow/offline/404 original artwork. The previous on-demand-only external thumbnail URLs could also fail on a poor connection, leaving a blank card; no longer acceptable.
2. The PvP artwork loader assigns the thumbnail **before** requesting/decoding full-size `/card-art/{CARD_ID}.webp`. Original loads use a bounded 2/3/6 concurrency budget depending on device. If full artwork fails, the miniature remains visible. New dynamic `img src="/card-art/..."` in Lobby, Battlefield, choices, Card Played, Mana, attachment, Hand, Hero are also detected by a presentation-only DOM observer. Card Review iframe and progression images receive the same binding.
3. **Privacy:** The observer operates on `IMG` URLs *already rendered* with an explicit card ID from the viewer-safe UI. It does not resolve hidden opponent Hand, inspect deck state or replace face-down card backs. No unidentified art or guesswork.
4. S3's smaller URL-only mapping and lazy individual WebP requests were preferable for initial JS heap, but cannot guarantee a miniature when offline. The new inlined donor thumbnail table is a deliberate user-requested reliability/heap tradeoff. Only full-resolution decode remains deferred.

## QA and limitations

- Latest VS AI donor files compared directly: `rc42-card-thumbnails.js`, `rc42-card-art-loader.js`, Website `lobby-import-pvp-style.css` and mobile counter styles. The game donor was not copied into networking.
- **250/250** donor thumbnail bytes and separate WebP mirrored to both release variants.
- Chromium in-memory UI harness (390×844 portrait and 844×390 landscape, touch emulation): dynamic face-up `IMG` from `/card-art/` paints 96×134 miniature even when full art requests are blocked; card ID update loads the *new* miniature; added cards paint even offline; hidden Back-of-Card remains untouched; PASS glows; phase button boxes have a 14px separation. This is a synthetic UI test, **not a real mobile gameplay test**.
- The loader now intercepts a failed full-resolution image during capture before an older renderer can incorrectly substitute a Main Deck back. Review iframe documents use weak retention to avoid leaked references across reloads.
- Native Northflank `ws`, hosted Website and two actual Android/desktop browsers not verified; S3 remains a QA Candidate. The old S3 F19 Swap archival test caveat remains.
